# 고도화 점검 문서

Figma Make 수정본을 코드로 정리하면서 확인한 내용입니다. ✅ 반영됨 / ⚠️ 일부 반영(더미 수준) / ❌ 미반영(기획·디자인 결정 필요).

## 1. 이번에 정리한 것
- 화면 파일 8개(수천 줄) → 화면 1개 = 파일 1개(`src/screens/<영역>/`), 영역별 `index.ts`
- 하드코딩 데이터 → `src/data/*`, 화면 간 공유 데이터 → `src/data/mock/*` (시계·팀·선수·경기·예매)
- 이미지 파일명 정리(`src/assets/images`), 미사용 참고 이미지는 `docs/design-refs`로 이동
- Figma 전용 설정(`.figma/`, vite 플러그인, index.html 슬롯) 제거, 상대 base로 정적 배포 가능
- 화면 ID 배지 맵을 `SCREENS` 한 곳에서 파생(중복 제거)
- 디자인 룩(색·카드·토글)은 유지. 점선 빨간 토글(케이스 전환용)도 그대로 사용

## 2. 더미 데이터 기준
- 기준일 `2026-09-19(토) 15:30`, 오늘 경기: 삼성 홈(대구) 18:30 시작
- 모든 날짜·요일·상대팀·좌석·예매번호는 `data/mock`에서 파생. 같은 경기가 홈·일정·티켓·MY 예매내역에서 동일하게 보임
- 선수 등번호·이름·성적은 `players.ts` 한 곳. 라인업·기록·선수상세가 같은 값을 참조
- **가상 데이터**이며 실제 성적과 무관. 실제 이름을 쓰는 만큼 공개 시 권리·초상 이슈 확인 필요

## 3. 발견해서 고친 오류
| 위치 | 문제 | 조치 |
|---|---|---|
| 회원 탈퇴 | 사유 선택이 상태에 반영되지 않음 | 선택값 연동 |
| 엘도라도 | 실시간 표시가 항상 켜짐 | 경기 상태 연동 |
| 기록 | 정렬 버튼 무반응, 팀기록 탭 비어 있음 | 정렬·팀기록 구현 |
| 일정 | 달력 요일 오프셋 오류, 월 이동 불가 | 계산 수정, 월 이동 |
| 알림 | 링크 없는 항목 클릭 시 오동작, 읽음 처리 미연결, 벨 점 항상 표시 | 연결 |
| 날짜 전반 | 2024/2025/2027 혼재, 요일 불일치 | 단일 기준일로 통일 |
| 선수 | 등번호·이름이 화면마다 다름 | `players.ts` 단일화 |

## 4. 야구 앱 케이스 체크리스트
**경기 상태**
- ✅ 경기 전 / 라인업 발표 전·후 / 진행 중 / 종료 (홈 `MATCH_STATES`)
- ✅ 우천 지연, 우천 취소(순연), 연장전, 무승부, 강우콜드 (일정·홈)
- ⚠️ 서스펜디드 게임, 더블헤더, 노게임(5회 미만 강우) — 일정 표기만 가능, 흐름 없음
- ⚠️ 포스트시즌(와일드카드·준PO·PO·KS) — 라벨 구조만 있고 시리즈 상태·예매 방식 없음
- ❌ 올스타전·시범경기·원정 응원 일정 구분

**티켓**
- ✅ 예매 오픈 전 / 선예매(멤버십) / 일반 예매 / 매진 / 예매 마감 / 순연
- ✅ 취소 마감(경기 4시간 전) 지난 경기 처리, 우천 취소 시 자동 환불 안내
- ⚠️ 부분 취소(여러 매), 좌석 변경, 양도 후 취소 — 문구만 있음
- ❌ 결제 실패·타임아웃, 대기열, 예매 중 좌석 선점 만료
- ❌ 어린이·장애인·경로 할인 증빙, 단체 예매

**라인업·기록**
- ✅ 발표 전 안내 문구, 양 팀 라인업, 선발 투수 전날 예고
- ⚠️ 선수 교체·대타·대주자, 선발 변경(부상 직전 교체) 반영
- ❌ 선수 등록/말소, 부상자 명단, 2군 경기(퓨처스) 라인업 상세

**알림**
- ✅ 읽음/안읽음, 모두 읽음, 링크 있는 항목 이동, 빈 상태
- ❌ 알림 설정 세분화(경기 시작/라인업/우천/예매 오픈), 야간 수신 제한, 푸시 권한 거부 시 안내

**공통 상태**
- ❌ 네트워크 오류·로딩·재시도, 서버 점검, 강제 업데이트
- ❌ 비로그인 상태 접근 제한 화면(로그인 유도), 세션 만료
- ❌ 다국어·접근성(폰트 크기, 스크린리더 라벨), 다크 모드
- ❌ 시즌 오프(비시즌) 홈 — 경기 없는 기간 콘텐츠

## 5. 정보 구조(IA) 점검 포인트
- 메뉴 설명서(`app-menu-descriptions.md`)와 실제 라우트 대조 시, 메뉴에는 있으나 상세 화면이 와이어프레임 수준인 곳이 다수 (`Placeholder` 사용 화면)
- 홈·경기 대시보드·라운지 대시보드가 서로 비슷한 구성 — 역할 구분 필요
- 티켓 → 예매 흐름(경기 선택 → 좌석 → 결제 → 완료)이 단일 플로우로 이어지는지 확인 필요
- 케이스 전환 토글은 프로토타입용입니다. 개발 인계 전 상태 정의서로 옮기는 것을 권장

## 6. 코드 개선 후보
- 미사용 상태/변수 18건(`pnpm typecheck`에 `noUnusedLocals`를 켜면 표시): GameDashboard, BlueSignal, Diary, MyHome, Signup, EditProfile. 와이어프레임 잔재라 동작 영향 없음
- 라우트 단위 `React.lazy` 분할(현재 번들 한 덩어리)
- 화면 내 반복 SVG 아이콘 → 공용 아이콘 컴포넌트
- 실제 API 연동 시 `data/` 를 서비스 레이어로 교체. 화면은 `mock/` 함수 시그니처만 의존하도록 유지
